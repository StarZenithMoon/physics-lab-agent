# 科学测评量表 v1

本量表用于仓库随附的24题公开评测集。权重、阈值和分档由本项目设计。方法依据见[来源与版本](../references/metrology-sources.md)，逐题判据见public-cases.json的expected。

## 1. 六项评分：评价处理能力

| 项目 | 分值 | 具体观察 | 判分方式/依据 |
| --- | --- | --- | --- |
| 数据与溯源 data | 15 | 列、单位、同条件重复、缺失/异常、转换、原始只读；事实和假设分开 | 逐题输入与实际输出核对；原始资料、共同数据规范 |
| 测量模型与假设 model | 20 | 被测量/分析目标、物理依据、修正符号、相关来源、定义域、范围与重要缺项 | 人工复核；GUM-6、NIST第5节及本题模型 |
| 数值/任务结果 outcome | 25 | 估计值、参数、u、协方差、区间或应有的澄清状态 | 独立参考断言；NIST认证值、可解析数学、GUM例题。澄清题检查result=null/缺项/status，不要求编数字 |
| 方法适用性 method | 20 | A/B转换、s与u(mean)、权重/协方差、约束/ODR、一阶近似、MC/矩存在、概率与覆盖 | 每题按capabilities生成具体检查要求，再人工查内容/代码；GUM/JCGM101/NIST及软件官方接口 |
| 运行证据与复现 reproducibility | 15 | 命令/代码、版本、真实轨迹、证据文件、关键量独立复算；MC种子/样本/区间精度 | 文件自动检查×人工档位。已有JSON不等于执行真实，不能只信Agent自报 |
| 结果表达 reporting | 5 | 单位、不确定度类别、覆盖含义、保护位数与最终修约、局限/来源、下一步 | 内容复核；NIST第7节及题目指定的报告约定。四个标题只作兼容格式诊断 |

复核有数值的报告时，将正文最终展示值与未修约证据对照。遵循题目明确规定的修约规则；题目只要求保护位数时核对该要求。分别记录正文展示问题和机器 JSON 提前修约问题，只检查题目实际要求的输出。

只检查题目适用的方法。拟合题不必为了得分硬跑MC；单一分辨力题不必虚构完整仪器预算；缺项题不必执行无意义数值程序。报告整理仍是各Skill的交付职责和模板，不新增排版Skill。

五个人工维度采用统一档位：1=本题所有适用要求有证据且无实质错误；0.5=主要方向正确但存在明确的非决定性遗漏/解释不足；0=缺失、错误或无可核验证据。每项必须填写原因和具体文件/段落/代码位置。不得只写“通过”。核心科学项只有1才过门槛，0.5也不能被漂亮格式抵消。量表之外发现决定性错误记到对应维度和理由，不靠临时加权修改判据。

总分为六项加权和；outcome为该题固定断言通过比例，reproducibility为文件合规比例×人工档位。缺失复核按0产生**暂计分**，同时标 `pending_review`；不得用于正式曲线或选版。已经判错的完整人工复核仍是有效低分，不能因低分剔除。

## 2. 成功门槛与严重错误

`task_passed` 要求：全部结果断言、所需证据和非空Markdown通过，人工data/model/method/reproducibility均为1。reporting计5分，不因标题风格单独否决科学任务。`gate_passed` 保留关键断言/证据门槛并加入前述科学复核。总分高也可能任务未通过。

以下按相应维度判0并使任务不通过：编造观测/仪器/引用/执行；用错误模型得出无条件物理结论；重要单位错误；无依据删点；漏掉主导来源/相关性；U当u；声称有限总体方差但矩不存在；关键事实缺失仍编定量结果。存在有限制但题目允许的正确限定分析应可通过，不能因status=limited一律扣分。

## 3. 不同任务的重点

| 题型 | 额外重点 |
| --- | --- |
| 数据整理 | 保留原值与行号，重复/负数不自动删除，质量提示不等于原因证明 |
| 线性/非线性拟合 | 与参考模型/缩放一致；残差、收敛/可辨识性；参数与协方差顺序；已知uy不重复缩小协方差 |
| 约束/双侧误差拟合 | 自由参数关系与约束保留，ux/uy正确计入；不强求不适用后端 |
| 解析传播/相关输入 | 修正、来源转换、共享分量与协方差符号；小样本t与已知正态量分开 |
| 非线性/MC | 估计量定义、联合分布/定义域、样本精度、区间类型；零梯度和发散矩；两路差异不统一以5%判定 |
| 正确澄清 | 识别最小决定性缺项，说明影响与需补信息；避免因非必要背景而拒绝可解任务 |

现有24题逐题 `expected.rubric.criteria` 含五个人工要求，method根据该题能力标签补具体条件。不是只挂一个通用“科学正确”标签。输入、数值目标、容差、split均未因本次补量表改变。

容差在运行前按题目冻结：确定性计算用已记录的绝对/相对容差及参考精度；MC参考考虑样本数和抽样波动，并逐项检查端点，不能把真值误差容限等同测量不确定度。当前已有MC容差需在正式预试中用固定协议验证其误拒率；预试后若更改必须重建v0，不能用于凑当前版本通过。不要按“最后报告只有两位”放松机器结果判定。

[NIST StRD](https://www.nist.gov/itl/sed/products-services/statistical-reference-data-sets-strd)提供统计数值参考，不是物理模型有效性认证。每个认证值须匹配原模型、参数化及残差尺度，不能只比最终小数相近。

## 4. 复核文件与执行

先运行任务，再创建空白复核记录（不会自动打分）：

```text
python -m evaluation.rubric --split train --reports evaluation/runs/v0-train
python -m evaluation.evaluate --split train --reports evaluation/runs/v0-train --out results/v0-train-score.json
```

`_reviews/<task-id>.json` 位于批次目录、个题Agent输出之外。操作者填写reviewer及rubric各项value/reason/evidence；value只许0、0.5、1。记录绑定任务、题目判据、该题**全部输出文件**和已有_runner轨迹的SHA256，修改Markdown/代码/证据同样使复核过期。模板拒绝覆盖旧复核。需要更正时先存档旧记录，再重建并重新复核，不修改Agent原报告。

建议操作者先独立阅读报告、查看真实工具轨迹并复算关键量，再看版本身份；争议/临界案例第二次复核并保存差异。目前没有自动双人盲评服务；人工过程及判断仍可能有偏差，哈希只是绑定，不是认证或系统沙箱。任务Agent不得给自己填写operator复核。不得读取评分目录的权限仍需真实运行隔离才能强制保证。

## 5. 汇总、选版与错误归因

主要看任务成功率；同时报告六维分、逐能力成功率、证据合规、逐题失败与退步。当前程序输出逐题维度、总体成功率/证据/格式率；分组图、重复运行置信区间和成本汇总尚需后续生成，不宣称已有图表。

选版信号为三次科学量表总分的均值（最低增益取config.json），逐题平均分/关键门槛通过率/任务成功率不得退步。repeated.py已实现三次独立会话、有限重试和汇总，outer_loop只接受该批次；单次预试不能建v0。标准差与范围描述三次运行差异，不据此声称精确总体置信区间。完整协议见[RSI评测约定](../rsi/PROTOCOL.md)和evaluation/protocol.json。

参考[Inspect评分策略](https://inspect.aisi.org.uk/scoring-policy.html)区分：模型错误/未交付为失败；API/进程故障最多重试一次，保留全部尝试，重复失败阻止选版。fixed_files_changed为完整性失败，不自动重试。step_limit/incomplete_output/普通300秒timeout按预算下未完成记失败；网络时间也含在墙钟预算，明确API故障按故障协议处理。空白/过期复核为pending，判卷配置故障抛错，不冒充能力0分。

当前resource-v5：内存硬限/进程数/日志等资源超限作为该预算下失败，不自动重试；75%内存通知仅预警，不记失败；仅新增越界产物记boundary_violation任务失败，保存越界证据、不重试；固定文件被篡改、进程树清理、保存或隔离失败则停止批次，不能输出可选版分数。启动等待单独计时，等待耗尽不算模型科学错误，也不允许据此初始化v0。每条正式记录必须含有效资源额度及cleanup_verified=true、active_processes_after=0。旧中断数据不能与新资源条件混成同一次v0。

旧版诊断分数不与科学量表混比。

## 6. 开源框架采用范围

| 一手参考 | 采用什么 | 当前状态 |
| --- | --- | --- |
| [Inspect AI scorers](https://inspect.aisi.org.uk/scorers.html) | 数值、过程、解释分开判；score与聚合metrics分开；待判/工具故障与模型失败分开 | 采用设计，轻量本地判卷；未安装/直接接入Inspect |
| [SkillsBench](https://github.com/benchflow-ai/skillsbench) | 任务化Skill效果评测；固定其他条件做无Skill/初始/优化Skill对照 | 尚未执行消融；当前v0指已有三Skill版本 |
| [EdgeBench/SForge](https://github.com/ByteDance-Seed/EdgeBench) | work/judge分离、轨迹/预算、环境反馈 | 参考架构；未接容器，不报官方分数 |
| [GEPA](https://gepa-ai.github.io/gepa/api/optimize_anything/optimize_anything/) | 训练/选版/测试分离，领域evaluator驱动文本搜索 | 可选后续优化器；不提供物理标准答案或权重 |

科学评分来自计量学与实验事实，框架只帮助组织和记录判分。当前最合适的是保留OpenCode执行层和可审查的领域scorer，不为获得一个百分数同时迁移多套框架。
