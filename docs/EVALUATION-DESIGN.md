# 评测设计

## 目的

评测用于检查项目的数值结果、科学方法、证据质量和报告交付。任务 Agent 生成的自述不作为正确性证明；参考数值、运行产物和任务外复核分别记录。

## v3 公开案例与划分

本版本公开评测集包含 24 个案例，分为 train 10、selection 8 和 test 6。案例均为公开数据或明确标注的合成输入，逐题来源、判据和容差见 [案例索引](../evaluation/CASES.md) 与 public-cases.json。

train 用于发现问题并形成候选；selection 用于候选与基线比较；test 在选版后用于检查。所有案例文件均随仓库公开，因此 test split 不属于隐藏测试。本文及随附结果仅适用于该公开集合和其声明的运行条件。

## 评分与复核

公开案例使用项目的 scientific-rubric-v1 六维量表：数据 15、模型 20、结果 25、方法 20、复现 15、表达 5。数值断言由固定程序检查；方法、解释和证据由任务会话外的复核流程检查。任务成功、证据合规及格式合规分别报告。

评分权重和阈值是项目定义的评测设置，不代表某一标准机构的计量规范。任务特定的物理模型和仪器参数仍需有来源支持。

## 候选比较

候选生成只使用 train 反馈；候选在冻结的运行条件下复测 train 和 selection。test 内容不进入候选生成或版本选择。每个版本应记录 Skill 快照、依赖与模型标识、任务输入、运行预算、实际产物、评分和复核结果。

三次重复用于描述运行波动，不等于总体统计显著性检验。分数比较只有在数据、量表和运行条件一致时才有解释力。
